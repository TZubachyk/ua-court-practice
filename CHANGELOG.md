Усі зміни до скіла фіксуються тут. Формат — `[X.Y.Z] - YYYY-MM-DD`.

## [0.4.0] - 2026-05-14

### Додано
- **Кросплатформенний `setup-deps.sh`** — автоматично визначає ОС (macOS/Linux/Windows/WSL) і пакетний менеджер (brew/apt/dnf/yum/pacman/apk/winget/choco/scoop), встановлює всі залежності: Python3, Node.js, poppler, python-docx, Playwright, npm docx. На macOS встановить brew, якщо немає.
- **Playwright як фолбек** — коли curl не працює через CAPTCHA або JS-блоки, скіл автоматично перемикається на Playwright (headless Chromium). Працює для ЄДРСР, clarity-project, opendatabot.
- **Двоетапний парсер** — замість обрізки 30K символів: Етап A будує карту секцій рішення (з позиціями), Етап B витягує конкретну секцію за ключовим словом ±3000 символів. Жодна частина рішення не губиться.
- **Обов'язковий прогрес-чеклист** — верифікація кожної справи виводить рядок статусу (`[3/8]: №X — ✅/⚠`). Замінено мовчазний «бойовий» режим.
- **Авто-нумерація рядків** у `generate-docx.js` — поле `num` автоматично додає номер як першу комірку.

### Змінено
- Крок 0 у обох скілах: замість inline bash — виклик `setup-deps.sh`.
- Стратегії верифікації: додано Playwright як 4-й шлях після PDF-дайджестів, WebSearch і curl.
- Парсер: підтримка російськомовних рішень, діагностика при NOT FOUND.
- `workflow.md`: повністю синхронізовано зі SKILL.md (двоетапний парсер, без WebFetch).

## [0.3.0] - 2026-05-14

### Додано
- **Новий скіл `/єдрср-верифікація`** — суб-агент, який спавниться після основного скіла `/єдрср` і дотягує справи, які не вдалось верифікувати з першого проходу.
- **Крок 6.1 у `/єдрср`**: автоматичний запуск суб-агента верифікації після генерації документа — агент отримує свіжу сесію і повторно шукає reg-номери та повні тексти для ⚠-справ.
- Суб-агент верифікації: інвентаризація ⚠ і ✅ справ, 5 стратегій пошуку reg-номера, контрольна перевірка лінків, генерація `_verified.docx`, структурований звіт.
- **`plugin.json`**: масив `skills` для виявлення обох скілів після `plugin install`, заповнено author.
- **`package.json`** у `scripts/` — залежність `docx` оголошена локально.
- **`.claude/settings.json`** — дозволи на curl, python3, pdftotext, node без ручного підтвердження.
- **Підтримка російськомовних рішень** — regex парсера доповнено `ПОСТАНОВЛЕНИЕ ИМЕНЕМ|РЕШЕНИЕ ИМЕНЕМ|ОПРЕДЕЛЕНИЕ`.
- **Розумна обрізка довгих рішень** — замість 30K від початку тепер 15K від початку + 15K від кінця (де зазвичай «Позиція ВС»), з індексом секцій.
- **Діагностика при NOT FOUND** — парсер тепер показує перші 500 символів сторінки, щоб агент бачив CAPTCHA / maintenance / зміну структури.
- Оцінка часу виконання в README (5-15 хв основний, 3-5 хв верифікація).
- Інструкція встановлення `python-docx` у README.

### Змінено
- **`workflow.md` Фаза 3 переписана** — видалено застарілі інструкції WebFetch (суперечили SKILL.md), замінено на curl-first з секційним парсингом.
- `generate-docx.js`: валідація JSON на вході, видалено невикористаний імпорт `PageOrientation`.
- `reyestr-search-rules.md`: готові комбінації зроблені загальними (раніше були тільки про третю особу).
- TodoWrite зроблено опціональним (не всі контексти мають цей інструмент).
- Очищено порожню директорію `references/` у верифікаційному скілі.

### Виправлено
- Друкарська помилка «7-крокововим» → «7-кроковим» у CHANGELOG.

### Передісторія
Версія 0.3.0 — результат тестування v0.2 на кейсі про право заінтересованої особи на оскарження патенту. Основний агент знайшов 9 справ, але 3 лишились зі статусом ⚠ — при тому, що ці рішення доступні в ЄДРСР (наприклад, справа №760/21858/16-ц під reg-номером 82769284). Причина — основний агент вичерпав бюджет запитів або натрапив на тимчасові блоки CAPTCHA. Суб-агент верифікації вирішує цю проблему: свіжа сесія, окремий бюджет, цілеспрямований пошук конкретних справ. Додатково проведено повний аудит на 28 пунктів — виправлено всі знахідки.

## [0.2.0] - 2026-05-13

### Додано
- **Правило 9**: WebFetch для reyestr.court.gov.ua повертає реконструкцію — заборонено використовувати для повного тексту рішень.
- **Правило 10**: PDF-огляди ВС читати тільки через `curl + pdftotext`, а не WebFetch.
- **Правило 11**: Якщо джерело блокує 3 рази поспіль — одразу просити текст у користувача, не штовхатися.
- Нова секція «Бюджет роботи і зупинка»: м'які ліміти (30 запитів, ✅ < 3 → зупинись).
- Нова секція «Режими роботи»: бойовий (за замовчуванням, тільки фінальний звіт) і дебаг (поетапні апдейти).
- Готовий Python-скрипт для парсингу сирого HTML ЄДРСР прямо в SKILL.md (Крок 4).

### Змінено
- **Крок 4 «Верифікація» повністю переписано** як curl-first. WebFetch для повного тексту рішень — заборонений.
- Уточнено «Що скіл НЕ робить»: явно вписано заборону WebFetch для повного тексту і для PDF.

### Передісторія
Версія 0.2.0 — результат тестування v0.1 на кейсі про банкрутство (зміна реєстру кредиторів). У межах тесту WebFetch повернув реконструйований текст постанови ОП КГС ВС, що зловив anti-hallucination guard. Перехід на curl + парсинг HTML дав справжній текст. Випрацьовано нові правила і workflow.
