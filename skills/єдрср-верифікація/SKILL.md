# Скіл «ЄДРСР-верифікація» — суб-агент дотягування і перевірки

## Призначення

Цей скіл — **другий прохід** після основного скіла `/єдрср`. Він читає згенерований Word-документ, знаходить усі справи, де основний агент не зміг отримати повний текст або reg-номер з ЄДРСР, і **дотягує** їх: повторно шукає в реєстрі та дзеркалах, верифікує цитати, оновлює маркери впевненості з ⚠ на ✅ (або видаляє справу, якщо вона не підтверджується).

## Коли спавнити

### Автоматично (інструкція для основного скіла `/єдрср`)

Основний скіл `/єдрср` **ЗОБОВ'ЯЗАНИЙ** після генерації фінального Word-файлу спавнити цей скіл як суб-агента. Додай у кінець Кроку 6 (Звіт користувачу) скіла `/єдрср`:

```
Після видачі фінального звіту — ЗАВЖДИ спавни суб-агента:

Agent({

у репо ua-court-practice (шлях: {шлях до репо}).
Далі виконай верифікацію документа: {абсолютний шлях до .docx}
Аналітичний текст документа (для контексту): {вставити текст вступу/аналітики}
Перелік справ зі статусом ⚠: {перелік номерів справ і що відомо про них}
Перелік справ зі статусом ✅: {перелік номерів справ з reg-номерами}`

```

### Вручну

Користувач може викликати скіл напряму:

- «перевір цей документ з практикою» + прикріплений файл
- «дотягни рішення, які не знайшов»

## ПРИНЦИПИ РОБОТИ

### 1. Цей скіл — ревізор, не автор

Ти не створюєш нового аналітичного тексту і не шукаєш нові справи, яких не було в документі. Твоя робота — **дотягнути те, що не дотягнув основний агент**:
- Знайти reg-номери для справ зі статусом ⚠
- Отримати повний текст цих справ з ЄДРСР
- Перевірити, що цитати і позиції відповідають оригіналу
- Перевірити працездатність посилань для справ зі статусом ✅

### 2. Ти маєш свій власний бюджет запитів

Основний агент міг вичерпати свій бюджет або натрапити на тимчасові блоки ЄДРСР. У тебе — **свіжа сесія** і свої запити. Часто те, що не вдалось основному агенту через CAPTCHA або тайм-аут, вдається тобі з першої спроби.

### 3. Анти-галюцинаційні правила — ідентичні основному скілу

Усі 11 правил з `/єдрср/SKILL.md` діють без винятків. Зокрема:
- Заборонено цитувати без прочитання повного тексту
- Заборонено генерувати reg-номери з пам'яті
- WebFetch для reyestr.court.gov.ua — заборонений для повного тексту
- Тільки `curl` + парсинг сирого HTML

### 4. Перевірка залежностей (автоматично)

При старті — запусти кросплатформенний скрипт встановлення (той самий, що й у основному скілі):

```bash
bash {шлях_до_репо}/skills/єдрср/scripts/setup-deps.sh
```

Працює на macOS, Linux, Windows, WSL. Визначає ОС і пакетний менеджер автоматично.

### 5. Прогрес-вивід обов'язковий

Навіть як суб-агент у фоні — виводь прогрес обробки кожної справи. Коли суб-агент повернеться головному агенту, той покаже результати користувачу. Формат:

```

⚠ [1/3] № 760/21858/16-ц — шукаю reg-номер... знайдено: 82769284 → текст отримано → ✅
⚠ [2/3] № 910/13040/17 — шукаю reg-номер... знайдено: XXXXXX → текст отримано → ✅

✅ Цитати (вибірково 2 справи): відповідають оригіналу
```

### Крок 2. Інвентаризація справ

Склади два списки:

**Список A — справи ⚠ (потребують дотягування):**
Для кожної збери:
- Номер справи (наприклад, № 760/21858/16-ц)
- Що відомо: суд, дата, вторинне джерело, приблизний зміст
- Що потрібно знайти: reg-номер, повний текст, верифікація цитат

**Список B — справи ✅ (контрольна перевірка):**
Для кожної збери:
- Номер справи
- Reg-номер (з гіперлінку в таблиці)
- Ключові цитати, які потрібно звірити

### Крок 3. Дотягування справ зі списку A (⚠)

**КЛЮЧОВЕ РОЗУМІННЯ:** Задача верифікації — пошук **за номером справи** (зворотний пошук), а не за темою. Основний скіл шукає справи за ключовими словами (прямий пошук). Це різні стратегії. Для зворотного пошуку reg-номера працює ТІЛЬКИ:

1. **PDF-дайджести ВС** — найнадійніший шлях (тестово підтверджено)
2. **WebSearch за номером справи** — шукає згадки в статтях, де є лінк на ЄДРСР
3. **Прямий curl на ЄДРСР Review/{reg}** — коли reg вже відомий

**НЕ працює** (тестово підтверджено, не витрачай час):
- `curl` на clarity-project, opendatabot, youcontrol — всі блокують без JS
- Прямий пошук ЄДРСР за номером справи — CAPTCHA
- `curl` на iplex search — 404

Для КОЖНОЇ справи зі списку A виконай наступну послідовність:

**3.1. Пошук reg-номера через PDF-дайджести ВС (НАЙКРАЩИЙ ШЛЯХ)**

PDF-огляди судової практики ВС — офіційні збірники, де кожна справа має пряме посилання на ЄДРСР. Визнач, до якої юрисдикції/теми належить справа, і завантаж відповідний дайджест:

```bash
# Приклади PDF-дайджестів (перевір актуальні URL на supreme.court.gov.ua):
# IP/інтелектуальна власність:
curl -sL "https://supreme.court.gov.ua/userfiles/media/new_folder_for_uploads/supreme/intel_vlasnist_27_05_2021.pdf" -o /tmp/digest.pdf
# Далі шукай номер справи:
pdftotext -layout /tmp/digest.pdf - | grep -i -B2 -A5 "{номер_справи_без_суфіксу}"
# Наприклад: pdftotext -layout /tmp/digest.pdf - | grep -i -B2 -A5 "910/13040/17"
# Результат має вигляд: "...за посиланням https://reyestr.court.gov.ua/Review/86503966"
rm -f /tmp/digest.pdf
```

Щоб знайти ПРАВИЛЬНИЙ дайджест:
1. Визнач юрисдикцію: КГС (господарська), КЦС (цивільна), КАС (адміністративна)
2. Визнач тему: IP, банкрутство, земля, корпоративні спори тощо
3. Шукай PDF на https://supreme.court.gov.ua або через WebSearch:
```
site:supreme.court.gov.ua "огляд практики" "{тема}" filetype:pdf
```
або:
```
site:court.gov.ua/userfiles "огляд" "{тема}" filetype:pdf
```

**3.2. Пошук reg-номера через WebSearch (ДРУГИЙ ШЛЯХ)**

Якщо PDF не дав результату — шукай статті, де згадується номер справи з посиланням на ЄДРСР:

```
"{номер_справи}" "reyestr.court.gov.ua/Review"
```
або:
```
"{номер_справи}" "{суд}" "{дата}" постанова
```

Якщо стаття знайдена (pravo.ua, sud.ua, jurliga.ligazakon.net тощо) — витягни reg-номер через WebFetch або curl.

**3.3. Якщо reg-номер відомий — збережи ліди**

Основний агент міг згадати reg-номер у вторинних джерелах або користувач надав його. Якщо reg вже є — одразу переходь до верифікації повного тексту (3.4).

**3.2. Верифікація повного тексту**

Коли reg-номер знайдено — фетчни повний текст через curl (НЕ WebFetch!). Використовуй двоетапний парсер, ідентичний основному скілу `/єдрср` (Крок 4.1):

**Етап A — карта секцій:**
```bash
curl -sL -A "Mozilla/5.0" "https://reyestr.court.gov.ua/Review/{reg-номер}" -o /tmp/rev_{reg-номер}.html
python3 << 'PYEOF'
import re
with open('/tmp/rev_{reg-номер}.html') as f: html = f.read()
text = re.sub(r'<script.*?</script>', '', html, flags=re.DOTALL)
text = re.sub(r'<style.*?</style>', '', text, flags=re.DOTALL)
text = re.sub(r'<[^>]+>', ' ', text)
text = text.replace('&nbsp;',' ').replace('&quot;','"').replace('&#39;',"'").replace('&amp;','&')
text = re.sub(r'\s+', ' ', text).strip()
m = re.search(r'ПОСТАНОВ[АИ] ІМЕНЕМ|РІШЕННЯ ІМЕНЕМ|УХВАЛА|ПОСТАНОВЛЕНИЕ ИМЕНЕМ|РЕШЕНИЕ ИМЕНЕМ|ОПРЕДЕЛЕНИЕ', text)
if not m:
    print(f'NOT FOUND — body not in raw HTML. First 500 chars: {text[:500]}')
    exit()
full = text[m.start():]
print(f'=== РІШЕННЯ ЗНАЙДЕНО: {len(full)} символів ===')
for p in [r'Позиція Верховного Суду', r'МОТИВИ:', r'Висновки суду', r'ПОСТАНОВИВ:']:
    for match in re.finditer(p, full, re.IGNORECASE):
        print(f'  [{match.start():>6}] {match.group().strip()}')
if len(full) <= 25000:
    print(full)
else:
    print(f'ТЕКСТ ДОВГИЙ ({len(full)} символів) — потрібен Етап B')
PYEOF
```

**3.3. Звірка з документом**

Якщо повний текст отримано:
1. Перевір, що позиція суду, яку основний агент описав у таблиці, **буквально** є в тексті рішення
2. Якщо є — зафіксуй: reg-номер, точну цитату з локацією, маркер → ✅
3. Якщо позиція є, але сформульована інакше — зафіксуй правильну цитату з локацією
4. Якщо позиції в тексті немає взагалі — зафіксуй: справа ❌, рекомендація: видалити з таблиці або переформулювати

**3.5. Ліміт спроб**

Якщо для конкретної справи після 2-3 спроб (PDF-дайджест + WebSearch) reg-номер не знайдено — залиш її зі статусом ⚠ і поясни, що саме спробував. Не витрачай час на шляхи, які тестово не працюють (clarity curl, opendatabot curl, iplex search — див. таблицю вище).

### Крок 4. Контрольна перевірка справ зі списку B (✅)

Для кожної ✅-справи:

1. Перевір, що лінк `https://reyestr.court.gov.ua/Review/{reg-номер}` повертає HTTP 200:
```bash
curl -sL -o /dev/null -w "%{http_code}" -A "Mozilla/5.0" "https://reyestr.court.gov.ua/Review/{reg-номер}"
```

2. Якщо HTTP 200 — вибірково перевір 1-2 ключові цитати з таблиці: фетчни повний текст і пошуком підтверди, що цитата є дослівною.

3. Якщо HTTP != 200 — зафіксуй проблему. Лінк може бути некоректний.

### Крок 5. Генерація оновленого документа

Після завершення перевірки — **пере-генеруй Word-документ** з оновленими даними:

1. Використай той же `scripts/generate-docx.js` із скіла `/єдрср`
2. Для справ, де ⚠ → ✅: оновити маркер, додати робочий гіперлінк, уточнити цитати
3. Для справ, де позиція не підтвердилась: видалити або переформулювати (з чітким поясненням у звіті)
4. Для справ, де ✅-лінк не працює: позначити проблему

Оновлений файл зберігати **поруч з оригіналом** з суфіксом `_verified`:
- Оригінал: `2026_05_14_Право_на_оскарження_патенту.docx`
- Оновлений: `2026_05_14_Право_на_оскарження_патенту_verified.docx`

## СТРАТЕГІЇ ПОШУКУ REG-НОМЕРА (тестово перевірено 14.05.2026)

Задача верифікації — **зворотний пошук**: є номер справи, потрібен reg-номер для лінку на ЄДРСР. Це принципово інший пошук, ніж у основному скілі (де шукають за темою/ключовими словами).

### Що працює (у порядку пріоритету):

**1. PDF-дайджести ВС — НАЙКРАЩЕ ДЖЕРЕЛО (тестово підтверджено)**

Офіційні PDF-огляди судової практики на supreme.court.gov.ua містять повні переліки справ з прямими посиланнями на ЄДРСР. Шлях: `curl + pdftotext + grep`.

```bash
# 1. Знайди потрібний дайджест через WebSearch:
#    site:supreme.court.gov.ua "огляд практики" "{тема}" filetype:pdf
#    site:court.gov.ua/userfiles "огляд" "{тема}" filetype:pdf
# 2. Завантаж і шукай:
curl -sL "{URL_дайджесту}" -o /tmp/digest.pdf
pdftotext -layout /tmp/digest.pdf - | grep -i -B2 -A5 "{номер_справи}"
# Результат: "...за посиланням https://reyestr.court.gov.ua/Review/86503966"
rm -f /tmp/digest.pdf
```

Відомі URL дайджестів:
- IP/інтелектуальна власність: `supreme.court.gov.ua/userfiles/media/new_folder_for_uploads/supreme/intel_vlasnist_27_05_2021.pdf`
- Інші теми: шукай через WebSearch `site:supreme.court.gov.ua "огляд практики"` або `site:court.gov.ua/userfiles`

**2. WebSearch за номером справи + "reyestr.court.gov.ua/Review"**

```
"{номер_справи}" "reyestr.court.gov.ua/Review"
```

Іноді фахові статті (pravo.ua, sud.ua, jurliga.ligazakon.net) містять прямі лінки на ЄДРСР.

**3. Прямий curl на ЄДРСР Review/{reg} — коли reg вже відомий**

Якщо reg-номер знайдено у PDF або статті — одразу фетчни повний текст.

**4. Playwright фолбек — коли curl не працює (CAPTCHA, JS-блоки)**

Якщо Playwright встановлено — він обходить JS-блоки і CAPTCHA, які ламають curl. Використовуй для ЄДРСР і дзеркал:

```bash
python3 << 'PYEOF'
import re
try:
    from playwright.sync_api import sync_playwright
except ImportError:
    print("PLAYWRIGHT NOT INSTALLED — skip")
    exit(1)
url = "https://reyestr.court.gov.ua/Review/{reg-номер}"
with sync_playwright() as p:

    page = browser.new_page()
    page.goto(url, wait_until="networkidle", timeout=30000)
    html = page.content()
    browser.close()
text = re.sub(r'<script.*?</script>', '', html, flags=re.DOTALL)
text = re.sub(r'<style.*?</style>', '', html, flags=re.DOTALL)
text = re.sub(r'<[^>]+>', ' ', text)
text = text.replace('&nbsp;',' ').replace('&quot;','"').replace('&#39;',"'").replace('&amp;','&')
text = re.sub(r'\s+', ' ', text).strip()
m = re.search(r'ПОСТАНОВ[АИ] ІМЕНЕМ|РІШЕННЯ ІМЕНЕМ|УХВАЛА|ПОСТАНОВЛЕНИЕ ИМЕНЕМ|РЕШЕНИЕ ИМЕНЕМ|ОПРЕДЕЛЕНИЕ', text)
if m:
    full = text[m.start():]
    print(f'PLAYWRIGHT: {len(full)} символів')
    print(full[:3000] if len(full) <= 25000 else f'Довгий текст, перші 3000:\n{full[:3000]}')
else:
    print(f'PLAYWRIGHT: NOT FOUND. First 500: {text[:500]}')
```

| Шлях | curl | Playwright |
|------|------|------------|

| court.opendatabot.ua | ❌ JS block | ✅ працює |

| reyestr.court.gov.ua/Review/{reg} | ⚠ іноді працює | ✅ працює |

### Що НЕ працює взагалі:

| Шлях | Чому |
|------|------|
| `curl` на youcontrol.com.ua | Загальна сторінка, не пошук |
| `curl` на iplex.com.ua/search.php | 404 Not Found |
| `site:reyestr.court.gov.ua` в WebSearch | Не індексується |

### Типові пастки:

- **Дефіси і суфікси в номері справи:** `760/21858/16-ц` — у `pdftotext` шукай без суфікса: `760/21858/16`
- **Декілька рішень у справі:** Одна справа може мати 5+ рішень у ЄДРСР. У PDF-дайджесті зазвичай лінк саме на постанову ВС
- **Дайджест може бути застарілий:** Якщо справа нова (2025-2026), вона може ще не потрапити в PDF-огляд. У цьому випадку WebSearch — єдиний варіант

## БЮДЖЕТ І ЗУПИНКА

- **До 20 пошукових/фетч-запитів** на весь прохід верифікації
- Якщо ⚠-справ багато (>5) — починай з тих, що найважливіші для аналітичного тексту документа
- Контрольна перевірка ✅-справ — вибіркова: 2-3 справи, не всі
- Якщо ЄДРСР блокує масово — зупинись, повідом, порекомендуй запустити верифікацію пізніше

---

## ЧОГО СКІЛ НЕ РОБИТЬ

- Не шукає нові справи, яких не було в оригінальному документі
- Не переписує аналітичний текст (тільки оновлює посилання і маркери в ньому)
- Не змінює структуру таблиці або формат документа
- Не додає нові стовпці чи рядки
- Не вигадує reg-номери — якщо не знайдено, справа лишається ⚠
- Не використовує WebFetch для повного тексту рішень (тільки curl або Playwright)
